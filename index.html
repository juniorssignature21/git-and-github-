Part 1: Installing Git

For Windows Users 💻

1Download Git

  1. Open your web browser
  2. Go to git-scm.com
  3. Click the big "Download for Windows" button
  4. Wait for the download to complete (approximately 50MB)

2Install Git

  1. Find the downloaded file in your Downloads folder
  2. Double-click the file (e.g., Git-2.43.0-64-bit.exe)
  3. Click "Next" through all screens (default options are fine)
  4. Click "Install" and wait for completion
  5. Click "Finish"

3Verify Installation

  1. Press the Windows key
  2. Type: cmd (opens Command Prompt)
  3. Press Enter
  4. Type: git --version
  5. Press Enter
git --version # Should output something like: git version 2.43.0
✅ Success! Git is now installed on Windows.

For Mac Users 🍎

1Check if Git is Already Installed

  1. Press Command + Space to open Spotlight
  2. Type: terminal
  3. Press Enter
  4. Type: git --version
  5. Press Enter

If you see a version number, Git is already installed! Skip to Part 2.

2Install Git (if needed)

Option A - Easiest Method:

  1. When you typed git --version, a popup might appear
  2. Click "Install" to install developer tools
  3. Wait 10-15 minutes for installation

Option B - Using Homebrew:

# First install Homebrew (visit brew.sh for the command) brew install git
✅ Success! Git is now installed on Mac.

For Linux Users 🐧

Ubuntu/Debian:

# Update package list sudo apt-get update # Install Git sudo apt-get install git # Verify installation git --version

Fedora:

sudo dnf install git
✅ Success! Git is now installed on Linux.

Part 2: Setting Up Git Configuration

Now that Git is installed, you need to tell Git who you are. This information will be attached to every change you make.

1Open Terminal/Command Prompt

  • Windows: Press Windows key, type cmd, press Enter
  • Mac: Press Command + Space, type terminal, press Enter
  • Linux: Press Ctrl + Alt + T

2Set Your Name

git config --global user.name "Your Name" # Example: git config --global user.name "John Smith"

3Set Your Email

git config --global user.email "your.email@example.com" # Example: git config --global user.email "john.smith@gmail.com"
⚠️ Important: Use the same email address you'll use for GitHub!

4Verify Your Settings

git config --list # You should see your name and email in the output

5Set Default Branch Name (Optional but Recommended)

git config --global init.defaultBranch main # Sets 'main' as the default branch name for new repositories
✅ Success! Git now knows who you are.

Part 3: Creating a GitHub Account

GitHub is a website where you can store your code online, collaborate with others, and showcase your projects.

1Go to GitHub

  1. Open your web browser
  2. Go to github.com

2Sign Up

  1. Click the "Sign up" button (top right corner)
  2. Enter a username (e.g., johnsmith123)
  3. Enter your email address (same one you used in Git config!)
  4. Create a strong password
  5. Click "Continue"
💡 Tip: Your username will be part of your profile URL: github.com/yourusername

3Verify Your Account

  1. Complete the puzzle to prove you're human
  2. Click "Create account"
  3. Check your email inbox
  4. Click the verification link or enter the code

4Complete Setup

  1. Answer GitHub's welcome questions (or skip them)
  2. Choose the free plan
  3. Click "Continue"
✅ Success! You now have a GitHub account. 🎉

Part 4: Setting Up SSH Keys

SSH keys provide a secure way to authenticate with GitHub without entering your password every time.

What are SSH Keys?

SSH keys are like a special password that your computer shares with GitHub. They come in pairs:

  • Private key: Stays on your computer (never share this!)
  • Public key: Goes on GitHub (safe to share)

Generating SSH Keys

1Check for Existing Keys

# Mac/Linux: ls -la ~/.ssh # Windows (in Git Bash): ls -la ~/.ssh

If you see files named id_rsa.pub or id_ed25519.pub, you already have SSH keys!

2Generate New SSH Key

ssh-keygen -t ed25519 -C "your.email@example.com" # Replace with your GitHub email

When prompted:

  1. "Enter file to save the key": Press Enter (uses default location)
  2. "Enter passphrase": Press Enter for no passphrase, or type a secure passphrase
  3. "Enter same passphrase again": Press Enter or retype your passphrase
⚠️ Note: If ed25519 doesn't work, use: ssh-keygen -t rsa -b 4096 -C "your.email@example.com"

3Add SSH Key to SSH Agent

On Mac/Linux:

# Start the SSH agent eval "$(ssh-agent -s)" # Add your key ssh-add ~/.ssh/id_ed25519

On Windows (Git Bash):

eval "$(ssh-agent -s)" ssh-add ~/.ssh/id_ed25519

4Copy Your Public Key

On Mac:

pbcopy < ~/.ssh/id_ed25519.pub # Copies key to clipboard

On Linux:

cat ~/.ssh/id_ed25519.pub # Then manually copy the output

On Windows (Git Bash):

clip < ~/.ssh/id_ed25519.pub # Copies key to clipboard

5Add SSH Key to GitHub

  1. Go to github.com and log in
  2. Click your profile picture (top right)
  3. Click "Settings"
  4. In the left sidebar, click "SSH and GPG keys"
  5. Click "New SSH key" (green button)
  6. Give it a title (e.g., "My Laptop")
  7. Paste your public key in the "Key" field
  8. Click "Add SSH key"
  9. Confirm with your GitHub password if prompted

6Test Your Connection

ssh -T git@github.com

You should see a message like:

Hi yourusername! You've successfully authenticated, but GitHub does not provide shell access.
✅ Success! Your SSH key is set up and working. 🔐

Part 5: Creating Your First Repository

Method 1: Create Repository on GitHub First

1Create New Repository

  1. Log in to GitHub
  2. Click the "+" symbol (top right)
  3. Select "New repository"

2Fill in Repository Details

  • Repository name: my-first-project (no spaces!)
  • Description: "My first GitHub repository"
  • Visibility: Choose "Public" (for learning)
  • ✓ Check: "Add a README file"
  • Add .gitignore: None (for now)
  • Choose a license: None (for now)

3Create Repository

  1. Click the green "Create repository" button
  2. You'll see your new repository with a README.md file
✅ Success! You've created your first GitHub repository! 🎉

Method 2: Create Local Project and Push to GitHub

1Create a Project Folder

# Navigate to Documents folder cd ~/Documents # Mac/Linux cd Documents # Windows # Create new folder mkdir my-local-project # Enter the folder cd my-local-project

2Create Files

Create an index.html file:

<!DOCTYPE html> <html> <body> <h1>Hello World!</h1> <p>This is my first project!</p> </body> </html>

Create a README.md file:

# My Local Project This is my first local project that I'm pushing to GitHub!

3Initialize Git Repository

git init # Output: Initialized empty Git repository

4Check Status

git status # Shows untracked files in red

5Add Files to Staging Area

git add . # The dot means "add all files" # Or add files individually: git add index.html git add README.md

6Commit Your Files

git commit -m "Initial commit - added index.html and README"

7Create Repository on GitHub

  1. Go to GitHub and click "+" → "New repository"
  2. Name it: my-local-project
  3. Important: Do NOT check "Add a README file"
  4. Click "Create repository"

8Connect Local to GitHub

After creating the repository, GitHub shows you commands. Use the SSH URL:

# Add remote repository git remote add origin git@github.com:yourusername/my-local-project.git # Verify connection git remote -v

9Push to GitHub

git push -u origin main # -u sets upstream, so next time you can just use: git push
✅ Success! Your local project is now on GitHub! 🚀

Part 6: Understanding Git Basics

The Three States of Git

  1. Modified: You've changed a file but haven't saved it to Git yet
  2. Staged: You've marked a modified file to go in your next commit
  3. Committed: The file is safely stored in your Git database

Essential Git Commands

Check Status

git status # Shows which files are modified, staged, or untracked

Add Files to Staging

git add filename.txt # Add specific file git add . # Add all files git add *.js # Add all JavaScript files

Commit Changes

git commit -m "Your commit message" git commit -am "Add and commit in one step" # For tracked files only
💡 Writing Good Commit Messages:
  • Be clear and concise
  • Use present tense ("Add feature" not "Added feature")
  • Explain what and why, not how
  • Examples: "Fix login button bug", "Add user profile page", "Update README with installation instructions"

View Commit History

git log # Full history git log --oneline # Compact view git log --graph # Visual branch graph

View Changes

git diff
